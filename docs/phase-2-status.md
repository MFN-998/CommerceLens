## What the warnings mean

These findings are preserved source limitations, not reasons to invent corrected rows.
The [full report](data-quality-report.md) and [JSON evidence](data-quality-report.json)
are authoritative for all checks; counts below can overlap.

- Geography contains 261,831 excess exact duplicate records and nonunique ZIP prefixes.
  A broad coordinate screen flags 31 rows. Customer and seller ZIP coverage gaps affect
  278 and 7 rows respectively.
- There are 547 orders with multiple review records. Neither `review_id` nor `order_id`
  alone is a unique review key; their pair is unique and non-null in this release.
- Event sequences include 166 carrier handoffs before purchase, 1,359 before approval,
  61 customer deliveries before approval, and 23 before carrier handoff. Delivered
  orders also include 14 missing approval, 2 missing handoff, and 8 missing delivery times.
- Product category/name/description/photo attributes are missing for 610 products;
  physical dimensions/weight have two missing values each. Thirteen product rows have
  a non-null category without a translation.
- Source zeros, undefined payment types, missing child records, and unusually distant
  shipping deadlines remain visible in the report.
- 275 orders have both multiple items and multiple payment components. Joining these
  sources on `order_id` produces 117,601 rows. Aggregate to an explicitly chosen grain
  before combining monetary measures in the warehouse.

The first diagnostic pass reported 27 warning checks. Review broadened lifecycle tests
to every pair of available events; the final report has 29. This changed diagnostic
coverage, not the source data or the staged values.

## Verification commands

From the repository root:

```powershell
uv run --locked --group data ruff check .
uv run --locked --group data ruff format --check .
uv run --locked --group data pytest
uv run --locked --group data python -m src.validation.run
uv run --locked --group data python -m src.ingestion.olist --verify
```

The failure-path tests cover tampered/missing/extra source files, conflicting manifests,
raw restoration, malformed CSV records, unparseable values, invalid composite keys,
orphan references, unavailable review evidence, and preservation of previous staging
on failure. Fixtures also verify literal `NA`, leading-zero identifiers, multiline
review text, UTF-8 BOM handling, and deterministic repeated staging.

One existing Starlette/AnyIO deprecation warning remains in API tests. No Phase 2
frontend files changed; the prior Phase 1 frontend checks are recorded in its separate
[status document](phase-1-status.md). Remote CI and other operating systems were not tested.
